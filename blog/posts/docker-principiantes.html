Docker para principiantes: Contenedores, imágenes y primeros pasos

Si alguna vez has escuchado a un desarrollador decir "en mi máquina funciona", sabes exactamente por qué existe Docker. Esa frase es el síntoma de un problema que Docker resuelve de raíz: las diferencias entre entornos de desarrollo, testing y producción. En esta guía vas a aprender qué es Docker, cómo funciona y cómo empezar a usarlo desde cero.

¿Qué es Docker?

Docker es una plataforma de código abierto que permite empaquetar aplicaciones y todas sus dependencias en unidades llamadas contenedores. Un contenedor es como una caja que incluye tu código, las librerías, las herramientas del sistema y la configuración necesaria para que la aplicación funcione. Esa caja se puede ejecutar en cualquier máquina que tenga Docker instalado, sin importar el sistema operativo ni la configuración del equipo.

Según encuestas recientes, más del 70% de las empresas de tecnología usan Docker en producción. En 2026, es una habilidad fundamental para cualquier desarrollador backend, DevOps o full stack.

Contenedores vs Máquinas Virtuales

Para entender Docker, primero hay que entender la diferencia entre contenedores y máquinas virtuales (VMs):

  • Máquinas virtuales: cada VM incluye un sistema operativo completo, consume gigabytes de espacio y tarda minutos en iniciar. Tienen su propio kernel y virtualizan hardware.
  • Contenedores: comparten el kernel del sistema operativo anfitrión, ocupan megabytes y se inician en segundos. Solo incluyen la aplicación y sus dependencias, no el sistema operativo completo.

Piensa en una VM como una casa independiente con todos los muebles, y un contenedor como un departamento en un edificio que comparte la infraestructura (agua, electricidad) con los demás departamentos.

Conceptos fundamentales

Antes de escribir comandos, necesitas entender estos tres conceptos clave:

Imagen (Image)

Una imagen es una plantilla de solo lectura que contiene las instrucciones para crear un contenedor. Es como una receta de cocina o un plano de construcción. Las imágenes se construyen en capas y cada instrucción en el Dockerfile crea una nueva capa.

Contenedor (Container)

Un contenedor es una instancia en ejecución de una imagen. Puedes tener varios contenedores ejecutándose a partir de la misma imagen, cada uno aislado de los demás. Los contenedores son efímeros por diseño: cuando los eliminas, los datos dentro se pierden (a menos que uses volúmenes).

Docker Hub

Es el registro público de imágenes de Docker. Aquí puedes encontrar imágenes oficiales de Node.js, Python, PostgreSQL, Nginx y miles más. Es como npm o pip, pero para contenedores.

Instalación de Docker

Docker está disponible para Windows, macOS y Linux:

  • Windows / macOS: descarga Docker Desktop desde docker.com. Incluye interfaz gráfica y todo lo necesario.
  • Linux: usa el gestor de paquetes de tu distribución. En Ubuntu/Debian:
sudo apt update
sudo apt install docker.io
sudo systemctl enable --now docker

Verifica que Docker se instaló correctamente:

docker --version

Comandos esenciales

Tu primer contenedor

docker run hello-world

Este comando descarga la imagen hello-world desde Docker Hub y ejecuta un contenedor que imprime un mensaje de confirmación y se detiene.

Ejecutar un servidor web

docker run -d -p 8080:80 nginx

Explicación: -d ejecuta el contenedor en segundo plano (detached), -p 8080:80 mapea el puerto 8080 de tu máquina al puerto 80 del contenedor. Si abres http://localhost:8080 verás la página de bienvenida de Nginx.

Gestión de contenedores

# Listar contenedores en ejecución
docker ps

# Listar todos los contenedores (incluyendo detenidos)
docker ps -a

# Detener un contenedor
docker stop <id_o_nombre>

# Eliminar un contenedor
docker rm <id_o_nombre>

# Ver logs de un contenedor
docker logs <id_o_nombre>

Gestión de imágenes

# Listar imágenes locales
docker images

# Descargar una imagen
docker pull node:20-alpine

# Eliminar una imagen
docker rmi <nombre_imagen>

Crear tu propia imagen con un Dockerfile

El Dockerfile es un archivo de texto que contiene las instrucciones para construir una imagen personalizada. Aquí tienes un ejemplo para una aplicación Node.js:

# Dockerfile
FROM node:20-alpine

WORKDIR /app

COPY package*.json ./
RUN npm install

COPY . .

EXPOSE 3000

CMD ["node", "index.js"]

Cada instrucción crea una capa en la imagen:

  • FROM: define la imagen base (Node.js 20 sobre Alpine Linux, una distribución muy ligera).
  • WORKDIR: establece el directorio de trabajo dentro del contenedor.
  • COPY: copia archivos del host al contenedor.
  • RUN: ejecuta comandos durante la construcción (instalar dependencias).
  • EXPOSE: indica el puerto que usará la aplicación (es documentación, no publica el puerto).
  • CMD: define el comando que se ejecutará al iniciar el contenedor.

Para construir la imagen:

docker build -t mi-app:v1 .

Para ejecutarla:

docker run -d -p 3000:3000 mi-app:v1

Docker Compose: múltiples contenedores

Cuando tu aplicación necesita varios servicios (una API, una base de datos, un caché), Docker Compose te permite definirlos todos en un archivo YAML y levantarlos con un solo comando:

# docker-compose.yml
services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DB_HOST=db
    depends_on:
      - db

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: miapp
      POSTGRES_USER: usuario
      POSTGRES_PASSWORD: contraseña
    volumes:
      - pg_data:/var/lib/postgresql/data

volumes:
  pg_data:

Para iniciar todo:

docker compose up -d

Para detener y eliminar todo:

docker compose down

Docker Compose es ideal para desarrollo local y entornos de prueba. Te permite replicar la infraestructura de producción en tu máquina con solo un archivo de configuración.

Volúmenes: persistencia de datos

Los contenedores son efímeros: cuando los eliminas, los datos desaparecen. Los volúmenes permiten persistir datos fuera del contenedor:

# Crear un volumen
docker volume create mis_datos

# Montar el volumen en un contenedor
docker run -v mis_datos:/app/data mysql

Los volúmenes se almacenan en el sistema de archivos del host y Docker los gestiona automáticamente. Son la forma correcta de manejar datos persistentes como bases de datos o archivos subidos por usuarios.

Buenas prácticas

  • Usa imágenes oficiales y ligeras: prefiere alpine o slim para reducir el tamaño de la imagen.
  • No ejecutes contenedores como root: crea un usuario dentro del Dockerfile para mayor seguridad.
  • Usa .dockerignore: como .gitignore, evita copiar archivos innecesarios (node_modules, .git) al contenedor.
  • Una sola responsabilidad por contenedor: no pongas la base de datos y la API en el mismo contenedor. Cada servicio en su propio contenedor.
  • Versiona tus imágenes: no uses latest en producción. Usa tags específicos como v1.2.3.

Conclusión

Docker ha revolucionado la forma en que desarrollamos y desplegamos software. Con los conceptos básicos que has aprendido aquí —imágenes, contenedores, Dockerfile y Docker Compose— ya puedes contenerizar aplicaciones y eliminar el "en mi máquina funciona" para siempre.

Empieza poco a poco: ejecuta un contenedor simple, luego crea un Dockerfile para un proyecto tuyo, y finalmente prueba Docker Compose para entornos multi-servicio. Es una habilidad que cualquier desarrollador debería tener en 2026.
