HTTPS y el cifrado SSL/TLS: cómo se protege tu web

Cada vez que el navegador muestra un candado 🔒 junto a la URL, está usando HTTPS. Pero detrás de ese candado hay una criptografía fascinante: un intercambio de claves, certificados digitales y cifrado que ocurre en milisegundos sin que lo notes. En esta guía vas a entender cómo funciona HTTPS y por qué es imprescindible en cualquier sitio web moderno.

HTTP vs HTTPS

HTTP es el protocolo con el que el navegador pide páginas al servidor. El problema: todo lo que viaja por HTTP va en texto plano. Contraseñas, números de tarjeta, mensajes… cualquiera en la red intermedia (WiFi, ISP, router) puede leerlos.

HTTPS es HTTP sobre TLS (Transport Layer Security), el estándar moderno (antes llamado SSL). TLS cifra los datos en tránsito: aunque un atacante los intercepte, solo verá una sopa de caracteres sin sentido. Además dos funciones extra:

  • Confidencialidad: solo tú y el servidor pueden leer el contenido.
  • Integridad: los datos no se pueden alterar en el camino sin ser detectado.
  • Autenticación: demuestra que estás hablando con el servidor correcto (gracias al certificado).

El concepto clave: criptografía asimétrica

TLS usa criptografía asimétrica: dos llaves matemáticas relacionadas.

  • La clave pública: se comparte con todo el mundo, se usa para cifrar.
  • La clave privada: solo el servidor la tiene, se usa para descifrar (y para firmar).

Es como una caja con dos cerraduras: cualquiera puede poner un mensaje y cerrar con la cerradura pública, pero solo quien posee la llave privada puede abrirla. Así, una mano desconocida puede mandarte datos seguros sin necesidad de haberse puesto de acuerdo sobre una contraseña en secreto.

El handshake TLS paso a paso

Cuando tu navegador abre https://amq7.xyz, ocurre un handshake en varias fases:

  1. Saludo: navegador y servidor se ponen de acuerdo en la versión de TLS y los algoritmos de cifrado (suite) que soportan.
  2. Certificado: el servidor envía su certificado digital, que incluye su clave pública y su identidad.
  3. Verificación: el navegador comprueba que el certificado fue emitido (firmado) por una Autoridad Certificadora (CA) de confianza, que el dominio coincide y que no está vencido. Los sistemas operativos y navegadores tienen preinstalada la lista de CA raíz.
  4. Clave de sesión: navegador y servidor acuerdan una clave simétrica temporal (más rápida), usando criptografía asimétrica para intercambiarla de forma segura.
  5. Conexión cifrada: a partir de ahí, toda la comunicación viaja cifrada con esa clave simétrica: rápido para el gran volumen de datos.

Todo este proceso toma milisegundos y es transparente para el usuario final.

¿Qué es un certificado SSL/TLS?

Un certificado es un archivo digital que identifica a un sitio (y enlaza su identidad con su clave pública) y que está firmado por una CA. Tipos según su cobertura:

  • Domain Validation (DV): solo verifica que el dominio te pertenece. Es el estándar en la web hoy.
  • Organization Validation (OV): verifica también datos de la organización.
  • Extended Validation (EV): verificación más exhaustiva; solía mostrar el nombre de la empresa en la barra. Poco uso hoy.

Existe la organización Let's Encrypt que emite certificados DV gratis y automáticamente (validez 90 días). Hoy casi todas las webs usan servicio gratis como Cloudflare o Let's Encrypt.

¿Hasta qué punto importa HTTPS para SEO y seguridad?

  • SEO: Google trata HTTPS como señal de clasificación. Desde 2024 se muestra word con candado; HTTP puro marca como "No seguro".
  • Seguridad del usuario: en 2026 HTTPS es obligatorio para contraseñas, pagos y datos personales.
  • Integridad del contenido: evita que un atacante inyecte anuncios o malware en las páginas que tu servidor envía.
  • Esencial para APIs y PWAs: muchas APIs del navegador (geolocalización, service workers, notificaciones) solo funcionan en contextos seguros HTTPS.

Cómo activar HTTPS en tu sitio

La buena noticia: en 2026 ya es trivial y gratuito. Si usas un hosting moderno o Cloudflare:

# Con Let's Encrypt + certbot (para un servidor propio)
sudo apt install certbot
sudo certbot --nginx -d mistdominio.com -d www.mistdominio.com

En plataformas (Cloudflare Pages, Vercel, Netlify, GitHub Pages) HTTPS se habilita automáticamente al publicar, sin configuración. Solo compra el dominio y listo.

Conclusión

HTTPS no es una opción de lujo: es la línea base de la web moderna. Con criptografía asimétrica, certificados firmados por CAs y un handshake eficaz, garantiza que tus usuarios puedan confiar en tu sitio. Y activarlo con certificados gratis y hostings con TLS automático no tiene razón para no hacerlo.
