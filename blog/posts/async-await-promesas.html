Async/Await y Promesas en JavaScript: La guía definitiva

Si alguna vez has intentado cargar datos de una API, leer un archivo o esperar un temporizador en JavaScript, te has topado con la programación asíncrona. Es uno de los conceptos más importantes y a la vez más confusos para quienes empiezan. En esta guía vamos a entenderlo todo desde la base: por qué existe la asincronía, cómo funcionan las promesas y cómo async/await hace que el código sea mucho más legible.

¿Qué es la programación asíncrona?

JavaScript es un lenguaje de un solo hilo (single thread). Esto significa que solo puede ejecutar una instrucción a la vez. Si una operación tarda 5 segundos, el navegador se congelaría durante ese tiempo. Para evitar esto, JavaScript delega las operaciones lentas (como peticiones de red, lectura de archivos o temporizadores) y sigue ejecutando el resto del código. Cuando la operación lenta termina, JavaScript vuelve a procesar el resultado.

Piensa en una cafetería: tú haces el pedido (inicias la operación), el barista prepara el café mientras tú esperas (operación en segundo plano) y cuando está listo te lo entregan (callback). No tienes que quedarte parado viendo cómo preparan el café; puedes mirar el móvil mientras tanto.

Callbacks: el primer intento

Antes de que existieran las promesas, la forma de manejar la asincronía era mediante callbacks: funciones que se pasan como argumento y se ejecutan cuando la operación termina.

function obtenerDatos(callback) {
  setTimeout(() => {
    callback("Datos cargados");
  }, 2000);
}

obtenerDatos(function(resultado) {
  console.log(resultado); // "Datos cargados" después de 2 segundos
});

El problema con los callbacks es el famoso callback hell: cuando tienes varias operaciones asíncronas anidadas, el código se vuelve ilegible.

obtenerUsuario(function(usuario) {
  obtenerPedidos(usuario.id, function(pedidos) {
    obtenerDetalle(pedidos[0].id, function(detalle) {
      console.log(detalle);
    });
  });
});

Promesas: la solución estructurada

Una Promesa es un objeto que representa un valor que puede estar disponible ahora, en el futuro o nunca. Tiene tres estados posibles:

  • Pending (pendiente): la operación aún no ha terminado.
  • Fulfilled (resuelta): la operación terminó con éxito.
  • Rejected (rechazada): la operación falló.

Crear una promesa

const miPromesa = new Promise((resolve, reject) => {
  const exito = true;

  setTimeout(() => {
    if (exito) {
      resolve("Operación exitosa");
    } else {
      reject("Algo salió mal");
    }
  }, 2000);
});

Consumir una promesa con .then() y .catch()

miPromesa
  .then(resultado => {
    console.log(resultado); // "Operación exitosa"
  })
  .catch(error => {
    console.error(error);   // "Algo salió mal"
  });

.then() se ejecuta cuando la promesa se resuelve, y .catch() cuando se rechaza. Además existe .finally() que se ejecuta siempre, sin importar el resultado.

Encadenar promesas

Una de las grandes ventajas de las promesas es que se pueden encadenar, evitando el callback hell:

obtenerUsuario()
  .then(usuario => obtenerPedidos(usuario.id))
  .then(pedidos => obtenerDetalle(pedidos[0].id))
  .then(detalle => console.log(detalle))
  .catch(error => console.error(error));

Si alguna promesa del encadenamiento falla, el .catch() al final capturará el error. Mucho más limpio que los callbacks anidados.

Async / Await: código asíncrono con synthax síncrona

Async/await es una sintaxis introducida en ES2017 que permite trabajar con promesas como si fueran código síncrono. No reemplaza las promesas, las hace más fáciles de leer.

async

La palabra clave async se coloca antes de una función y hace que esa función siempre devuelva una promesa.

async function saludar() {
  return "Hola";
}

saludar().then(console.log); // "Hola"

await

await solo puede usarse dentro de una función async. Hace que JavaScript espere a que la promesa se resuelva antes de continuar con la siguiente línea.

async function obtenerDatos() {
  const resultado = await miPromesa;
  console.log(resultado);
}

Ejemplo con fetch

El caso de uso más común: obtener datos de una API:

async function obtenerUsuario(id) {
  try {
    const respuesta = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);

    if (!respuesta.ok) {
      throw new Error(`Error HTTP: ${respuesta.status}`);
    }

    const usuario = await respuesta.json();
    console.log(usuario.nombre);
    return usuario;
  } catch (error) {
    console.error("Error al obtener usuario:", error.message);
  }
}

obtenerUsuario(1);

Fíjate en el try/catch: así se manejan los errores con async/await. Es exactamente igual que en código síncrono, lo que hace todo mucho más natural.

Promise.all: varias promesas en paralelo

Cuando necesitas hacer varias peticiones independientes, no tiene sentido esperar a que una termine para empezar la siguiente. Con Promise.all las ejecutas en paralelo y esperas a que todas terminen:

async function obtenerMultiplesUsuarios() {
  const ids = [1, 2, 3, 4, 5];

  try {
    const promesas = ids.map(id =>
      fetch(`https://jsonplaceholder.typicode.com/users/${id}`)
        .then(res => res.json())
    );

    const usuarios = await Promise.all(promesas);
    console.log(usuarios); // Array con 5 usuarios
  } catch (error) {
    console.error("Error en una de las peticiones:", error);
  }
}

Si alguna promesa falla, Promise.all rechaza todo. Para casos donde quieras que las demás continúen aunque una falle, usa Promise.allSettled().

Buenas prácticas con async/await

  • Siempre usa try/catch para manejar errores. Una promesa rechazada que no se captura puede causar errores silenciosos difíciles de depurar.
  • No abuses de await secuencial cuando las promesas son independientes. Si haces await a(); await b(); await c() y las tres son independientes, estás perdiendo tiempo. Usa Promise.all.
  • Usa nombres descriptivos para tus funciones async. Esto hace que el flujo del código se entienda de solo leerlo.
  • Evita usar await en el nivel superior del módulo (top-level await está disponible en módulos modernos, pero úsalo con cuidado).

Ejemplo completo: app del clima

Veamos un ejemplo práctico que combina todo lo aprendido:

async function obtenerClima(ciudad) {
  const apiKey = "TU_API_KEY";
  const url = `https://api.openweathermap.org/data/2.5/weather?q=${ciudad}&appid=${apiKey}&units=metric&lang=es`;

  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error("Ciudad no encontrada");

    const datos = await res.json();
    return {
      ciudad: datos.name,
      temperatura: Math.round(datos.main.temp),
      descripcion: datos.weather[0].description,
      humedad: datos.main.humidity
    };
  } catch (error) {
    throw new Error(`Error al obtener clima: ${error.message}`);
  }
}

async function mostrarClima() {
  try {
    const clima = await obtenerClima("Bogotá");
    console.log(`Clima en ${clima.ciudad}: ${clima.temperatura}°C, ${clima.descripcion}`);
  } catch (error) {
    console.error(error.message);
  }
}

mostrarClima();

Conclusión

La programación asíncrona es fundamental en JavaScript moderno. Las promesas resolvieron el problema del callback hell, y async/await hizo que el código asíncrono se lea como si fuera síncrono. Dominar estos conceptos te permitirá trabajar con APIs, bases de datos, archivos y cualquier operación que requiera tiempo, sin bloquear la interfaz de usuario.

JavaScript ha evolucionado muchísimo desde los callbacks. Hoy en día, con async/await, escribir código asíncrono es tan natural como escribir cualquier otra función.
